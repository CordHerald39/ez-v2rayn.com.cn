> 2026-10-04 来源核验：本文依据官方资料独立整理，未执行客户端 GUI、真实节点或设备实测。文中的验收步骤是操作建议。

## 当前节点失效，为什么连检查更新也失败
7.25.4 加入了更新连接路径的开关。官方 PR #10090 说明，检查更新窗口的“Update via proxy”默认启用并保存选择，涉及检查版本、下载更新、Geo 文件更新及定时检查。因此当前代理不可用时，更新请求也可能走进同一条失败路径。这个设置与订阅更新的连接方式分别管理，不能从订阅成功推断程序更新一定成功。

## 按两条路径做最小对照
先记录客户端版本、失败时间、请求对象和日志中的错误类型。打开检查更新窗口，核对“通过代理更新”的状态。若现有代理可用，先保持启用检查一次；若当前节点已无法连接，可关闭该项后再检查。直连网络必须能访问相应官方发布资源，否则关闭开关仍会失败。
只变更这一项，暂时不要同时更换 DNS、内核和节点。分别记录“获取版本信息”与“下载文件”的结果：检查成功而下载失败，说明两段请求的可达性还需继续核对。

## 根据错误决定下一步
| 现象 | 接下来核对 |
| --- | --- |
| 代理方式失败，直连成功 | 当前代理入口、节点与更新请求路径 |
| 直连失败，代理成功 | 当前网络对官方资源的可达性 |
| 两种方式都超时 | 网络、目标资源状态及具体连接错误 |
| 证书验证失败 | 系统时间与证书信任来源，不能按超时处理 |
这些是排查分支，不是对你的网络已经作出的诊断。遇到限制策略时，应遵循所用网络的管理要求。

## 完成后保存可解释的状态
成功取得版本信息后，仍要在官方发行页核对版本和资源。下载完成不等于安装成功，更不等于节点恢复。最后检查开关是否保留在你期望的状态，避免下次定时更新使用与本次记录不同的路径。更新前的资料备份参见[备份指南](/articles/backup-folder/)。
